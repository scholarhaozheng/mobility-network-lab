# 统一图件模板与接入规范 · R12

适用日期：2026-10-08。适用于 Boston、Hong Kong、Ann Arbor、Urbana–Champaign、Ithaca、Berkeley、Chicago、Pittsburgh 的当前科学图件；Sioux Falls 单列为演示基准，保留其既有内容。本文与 `FIGURE_STYLE_CONTRACT.json` 是同一规范的人读版和机器版。

## 1. 这次恢复的是什么

两个指定对话已完整阅读：旧主线61轮、后续交接5轮，并回查108条逐图原始审阅批注和实际绘图代码。最明确的选择是：“C的风格，A、B的配色，字体要serif字体（不是times，是serif）”。后续又明确要求所有图的城市／标题位置一致、题目贴近绘图区、减少空白、长文字移图外、不同算法另起一行，以及主页跳到大卷同一张图。

这里有三个不同层次，不能混淆：

- **用户确定的规则**：版式C、蓝绿／深蓝、serif非Times、统一层级、简短图内文字、真实数据与场景、去重复、同图定位。
- **既有代码实现参数**：15pt主标题、8.7pt城市栏、8pt标题与主体间隔等。它们是旧城当前样式的实际值，不是冒称用户逐项指定。
- **本轮执行检查**：自动检查字号、题目位置、单点伪轨迹、字体嵌入、图内长段、单位、源哈希与页面锚点。历史并没有“图内最多N个字”的数字规定，因此不编造一个历史字数上限。

既有选择已经明确，不再另做A/B/C风格选项。新的绘图任务必须先读本模板，再复用公共样式模块。

## 2. 每张图开始前必须填写的资料

|字段|必须回答的问题|
|---|---|
|图ID／城市|对应哪一个当前证据问题？图ID只用于追溯，不把失效章节序号画在标题里。|
|算法／方法|FW、Algorithm B、有限路径、Native、CG、LR、ADMM，还是数据输入／观测诊断？|
|实例|哪一个冻结模型、OD集合、rank／表示、版本和时间段？同城多个实例不能自动视为同一个实验。|
|数量／单位|person trips、PCE/h、PCE/finite horizon、PCE·min、minutes或无量纲，分别对应哪些面板？|
|科学问题|一句话说明图要回答什么；不能只写“展示结果”。|
|面板角色|各面板提供哪些独立信息？重复地图、重复统计、纯状态数字不为凑版面再画。|
|数据来源|实际读取文件／字段、精确SHA-256、行数和必要索引；不拿相近文件名代替绑定。|
|数据限制|没有全向量、只有一个端点、缺实际价格／恢复记录、无同实例LP、状态未通过等，明确写出。|
|图外说明|场景、缩写、单位转换、门槛、图的读法及模型／观测边界。|

该资料写入图件manifest和source sidecar。没有这些字段，不允许生成“看起来相似”的新图。

## 3. 标题、城市、字体和颜色

|位置／元素|统一实现|
|---|---|
|城市栏|左上方，在主标题上面；城市大写，青绿色 `#087f82`，DejaVu Serif bold，8.7pt。只可追加简短实例提示。|
|主标题|城市栏下方，左对齐；深蓝 `#132f51`，DejaVu Serif bold，15pt。用方法／问题命名，例如 `Frank–Wolfe physical-link flow`。|
|版本、规模、时段|保持算法名是主标题；短实例提示可在城市栏；较长版本、OD规模、时段放网页副标题／图注。不得让一整行状态码挤占标题栏。|
|面板标题|小写a、b、c加简短内容，11pt；同层级同字重、同位置。|
|坐标／色条标签|9pt，写数量与单位；不要只有裸缩写。|
|刻度／图例|通常8pt；小标签只有在实际显示仍可读时才用更小字号。|
|公式|`dejavuserif`数学字体；SVG文本可编辑，PDF嵌入TrueType。|
|道路背景|浅灰 `#dbe3e7`，细线，不与结果着色争抢注意力。|
|顺序色标|`#dfefed → #80c3bd → #278e98 → #14355a`；映射方法随数量性质说明。|
|差值色标|`#256482 → #f5f6f3 → #bb6749`，零居中，对称范围；不拿绝对流量的单向色标画有符号差。|
|其它系列|主要用青绿 `#087f82`、蓝 `#3773b7`、深蓝；不靠红／绿颜色单独判断通过与失败。|

不得用Times替换serif，也不能只在SVG外包一条CSS来宣称字体已统一；字体转成路径的旧图必须核对生成源。中文图注留在网页说明，不把长中文段塞进图内。

## 4. 空间、留白与图内文字

公共绘图模块在导出前测量真实文字和axes边界，再安放标题：主标题到绘图区约8pt，城市栏到主标题约5pt，外边距0.055英寸。不是仅设置一个固定top值后假定没有空白或重叠。

图内保留：城市、短标题、面板标识、必要坐标／色条单位、图例、门槛线的短标签和少量帮助读图的标注。以下应放图外：长背景、来源版权全文、已放行／待接收的过程说明、全部模型规模列表、方法结论段、复现路径、重复统计表。不能把门槛／单位一起删掉来获得“清爽”。

地图保持真实几何比例，不拉伸地图来填满卡片。宽度与高度由面板的信息量决定；如一个地图加一个直方图，要合理安排两者尺寸，不留下大块没有信息的区域。颜色条尽量靠近其所属面板。同排地图共享extent与可比的归一化；不同实例不强行共用不合理尺度。

统计热图和色条可以是Matplotlib本身的栅格子对象；这不等于把旧整张图片截图后粘进新画布。禁止用整图截图冒充可复现重绘。

## 5. 图型先匹配科学问题

|图类|当前应该怎么画|不可以做什么|
|---|---|---|
|道路／分区／接入|真实已保存区域、道路、分区与接入；俯瞰、浅灰底网、适量标识。|虚构几何、把来源范围当需求边界、把虚拟turn/access弧当物理道路叠加。|
|人口／家庭／就业|对应真实分区的空间量或全分区分布；新补充但未进入生成模型的字段明确隔开。|把估算、代理变量、后加字段写成已经用于模型或实际测量。|
|出行生成|production／attraction及purpose的真实数量，注明person trips和时段。|把生成和分布混成一个无法识别的问题。|
|出行分布|真实OD、完整已建模集合、intrazonal未建模与零值分开。|隐藏零值、只画top-k却称完整需求、随意改矩阵顺序。|
|方式选择|person数量／比例、广义费用、可用性各有明确单位。|把时刻表查询次数当乘客、把方式修订导致的需求变化当算法更好。|
|FW／B／有限路径|方法自身物理流量地图＋对应完整路段分布；比较时同实例、同范围、包含零路段。|仅用一个objective／gap小面板替代空间加载证据；用FW向量冒充B或Native。|
|Native|rank或表示变体成组；自身重构的绝对流量、对同实例参考的有符号差，以及有意义的真实过程诊断。|把26/52称不同算法；把未压缩80维通过追认成26/52压缩成功。|
|时间展开构造|有真实层／弧记录时画语义层次，并在该行第一张；具体computed column与graph context对应。|把地图坐标随便抬高做装饰3D、把静态turn-expanded图称时间网络。|
|CG|Phase I实际人工量；Phase II真实目标；完整图定价与实际新增路径。对应同图LP基准。|把容量slack写成OD unmet demand；把两phase各一条记录连成两轮收敛。|
|LR|bounds与可用gap、真实价格、真实恢复／自有路径池各有证据。|没有自身可行UB仍画0gap；把新hybrid通过写到旧纯LR名下。|
|ADMM|原单位可行性、primal consensus、rho-scaled dual、同图目标误差各自正确；保留必要门槛。|画rho history作主要证据；把PCE和minutes混在同一残差轴；把不可行x目标称可行上界。|
|观测／诊断|来源年份、记录／站点／车辆等单位及匹配证据等级清楚。|把候选关联当完整路由、把站点ID匹配称精确定位或标定。|

Boston和香港也是多个独立实例，不能仅因城市相同就混用其参考目标、单位或需求规模。旧规范的“地理图俯瞰”不禁止后来明确要求的真实时间层构造图。

## 6. 单点、两点、短过程如何处理

先查保存记录，再决定图型；不能通过增加插值点让曲线显得丰富。

- 只有初始化检查、一个端点、一次更新前后两个状态：有数据仍绘图。用真实保存点及相应门槛，明确 x 轴是迭代、阶段还是方法类别；没有中间状态就不补点。不能因为点数少就自动改成表格。
- 任何长度的真实保存过程都可以画；点数不等于更新数。一个点标明为初始检查／单轮状态，两个点标明为真实前后状态，多个点保留全部记录、阶段切换和冷启动／续算身份。
- 多个方法的端点：用方法类别散点或点—门槛对照，不把类别连成迭代曲线。各方法自己的物理流量地图和全路段分布仍为主图；端点图不能替代这些主图。纯计数或与现有图重复的量并入图注。
- 一条平线若确有很多真实记录，可以保留并解释；不得为了好看制造变化。没有价格变化、没有可行恢复时，直接说明，不画不存在的价格或UB。
- 对短T4，已保存的容量冗余证明支持“本实例硬容量不绑定”；它不能证明地理面积是原因。静态BPR的v/c>1与T4硬容量约束不是一个概念。

Ann新S600的1次FW更新、Urbana新418OD的0更新、三个城市小T4的短记录、Pittsburgh Native14轮及Chicago新hybrid36条必须分开写。完整说明仍接原R10逐项审计；新的展示模板不改变数值结论。

## 7. 页面卡片与同图接入

1. 各现实城市同一层级；Sioux Falls放在最后并标为演示基准。
2. 一个算法一行，算法名作主标题，版本／规模作副标题；不能把不同方法挤在同一组“最新图”里。
3. 一个分组只有一行时，1／2／3张分别均分该行；多行分组维持三列，不让最后一张忽然铺满整行。
4. 同排图片上沿对齐，图注起点也对齐；使用统一图题层级，不重复连续写两次Trip generation等阶段名。
5. 每项科学证据只保留一个当前展示。科学原件在本地归档中保留。失败尝试不进入主页、城市大卷、交互选择器或读者图表；成功实验的完整真实轨迹不删去早期尚未达到停止门的轮次。
6. 主页和大卷引用同一实际文件，主页Complete evidence指向那张图／表的准确锚点；折叠内的锚点打开时自动展开。
7. 归属同城的长版权notice只保留共享全文，每张图／表邻接短链接。原获准notice、caption、plot data原字节保留。
8. 没有对应数据时在原阶段中说明缺什么，不画占位结果，不用另一个实例填空。

## 8. 文件、代码与图件复现

推荐代码入口为 `tools/figures/style.py` 和其同目录的纯绘图命令。样式参数读取 `docs/assets/figure-contract-r12/FIGURE_STYLE_CONTRACT.json`。绘图命令只读已保存结果；不在导入时调用优化器、matcher或网络下载。

从公开数值数据重绘的每个输出包含SVG（文字可编辑且嵌入serif）、PNG（300dpi）、PDF（TrueType），再附source JSON和图外caption。原始数据公开条件不足时，不为齐全而导出受限plot data；在source记录公开可复现边界。图件代码、数值计算代码、资料获取、网页展示分开组织。

获准原件存放在原release目录且字节不变。本轮新图放独立presentation目录，并记录原件／输入SHA及导出SHA。它是本次用户授权的本地展示修订，不冒称仍是S0批准的同一张PNG字节。

## 9. 计算包与发布历史的边界

现有计算包仍有自己的版本：文档r19／计算r14。旧41条命令、200个pins、44条补充记录及108条实验目录的范围是Boston、Hong Kong、Sioux Falls和shared。六个新城市的展示证据已接收，不意味着该旧包已经有六城的一键计算配方。

本轮实际核验：旧ZIP的1106个成员哈希完整；当前candidate与旧ZIP存在展示文件差异，因此不能沿用历史“当前全包发布检查通过”的说法。此轮要整理纯绘图源和本地交付说明，不在没有新授权时commit、push或deploy，也不为了图更好看重跑科学计算。

每次真正发布前应按当时实际文件重新核查：源码／数据边界、可运行命令与环境、精确pins、manifest与ZIP成员一致、网页和同图链接、公开内容与notice、失败原始记录本地归档、当前网页只显示获接受的实验、计算／文档版本分账。历史green check只能作为历史证据。

## 10. 给ChatGPT或下一位执行者的必读约束

- 先读本模板和机器contract；不得自行换风格，也不得以“已经用了serif”代替图型与指标对齐。
- 每张图先写实例、指标、单位和面板作用，再画。以实际保存列和代码为准，不只依据网页标题。
- 只用已保存结果；不新增实验、不伪造迭代、不插值补点、不改变门槛、不用别的方法向量代替。
- 先处理短记录和重复证据的图／表选择，再处理字体、标题、留白。
- 长说明、来源和全部统计移到图外；必要轴标、单位和图例不能删。
- 方法名、版本、rank、时间尺度和不同需求分开；成功／失败按具体方法实例，不给整城涂绿。
- 保留每张旧获准图的原字节，当前图使用可追溯的新文件；不得让主页和大卷各用一个版本。
- 若来源不足以支持某种图，列明缺少的字段／向量／历史及公开边界，在相应方法处简洁说明未展示原因；不能借另一方法的数据补图，也不自动铺一张大表。
- 交付前逐张检查真实导出图，另做字体、文字溢出、图内长段、单位、哈希及锚点检查。不得用自动检查替代视觉检查，也不得无证据声称浏览器截图通过。

### 公开几何不足时的旧 SVG 排版例外

部分旧图只放行了完整 SVG，缺少可公开的完整几何数据。这些图采用 `vector-transform`：保留原科学图形、配色、投影及数值，仅重排标题和间距。新增城市名与标题为可编辑的 DejaVu Serif；旧图中已经转为路径的标注仍保留路径，不声称全部文字可编辑，也不称其为原始数据重绘。每幅 `.source.json` 单独记录渲染路线、原图哈希、科学几何核验和字体边界。
